# Verification round — October 16, 2026

## Result

Local username authentication, profiles, pixel editor, relationships and two-person rooms pass the checks below. The app is available at http://localhost:3210 using the existing SQLite account database. No games were added.

## Fixed during this round

- Rejected old-password sign-in if a recovery/password update completes during asynchronous password verification. A deterministic regression test pauses verification, performs recovery and confirms the stale login fails.
- Windows launcher waits for readiness, reuses an already-running Just Us server, and refuses another application's occupied port. Fresh startup and reuse were exercised; the isolated startup test server was stopped afterward.
- Compiled backup/restore tooling so production pruning does not remove its TypeScript runtime requirement. Tested a real compiled backup, valid restore and corrupt-backup rejection on isolated data.
- Browser CI now tests the compiled server/frontend, rather than only Vite development middleware.
- Added browser coverage for one-time account recovery across independent sessions and a subsequent password change. An initial test read the hidden key field before signup completed; it now waits for the recovery dialog and populated key.
- Disabled automatic Render deployments and documented the single-owner database lock's incompatibility with ordinary overlapping rolling deploys. This limitation remains; it requires maintenance replacements for this pilot.

## Checks performed

- `npm test`: 40 passed across 10 files.
- `npm run build`: TypeScript and compiled server/frontend passed.
- `E2E_COMPILED=1 npm run test:e2e`: seven passed together in Chromium. Includes independent room/account contexts, phone/tablet/desktop layouts, profile and relationship flows, privacy, third-person refusal, refresh/reconnect, recovery, password change and automated accessibility checks.
- `STATE_TOOL_COMPILED=1 npx vitest run tests/integration/backups.test.ts`: passed against emitted JavaScript.
- `node --check scripts/launch.mjs`: passed. Launcher startup, server reuse and foreign-service refusal verified with browser auto-open disabled.
- Main local `/health`: identifies `just-us`; `/ready`: healthy SQLite storage. Main preview retained; isolated launcher server removed.
- Account desktop screenshot inspected; browser assertions checked narrow-screen overflow. Prior visual checks are described in RELEASE_READINESS.md.
